## Engineering calls (Claude's, with reasoning)

1. **Resume re-hashes the existing `.part` from the start** rather than
   saving digest state. `MessageDigest` state can't be serialized portably.
   Re-reading ≤420 MB from internal flash costs seconds, which is less than
   the network time it saves.
2. **The filler uses `fallocate`** on `/sdcard/wp096-filler/` (the shared
   storage on `/data`, the same volume as the app's files). The
   [device probe](#device-the-tcl-65q77k) confirmed it allocates real blocks
   through FUSE and frees them exactly. It reserves the space without writing
   it, which matters for a ~15 GB filler. The script checks the filler's real
   size with `df`. It falls back to `dd` from `/dev/zero` only if `fallocate`
   fails, and refuses any fallback filler over 2 GiB rather than write it to
   flash.
3. **The power cut is the last interruption test**, after `kill -9` and
   `adb reboot` have passed. A fault the cheaper tests can catch is fixed
   before the TV is unplugged.
4. **`tools/Invoke-TvFiller.ps1` is PowerShell 7**, following Jeff's script
   convention. It drives `adb` from Windows (WP-085 lesson 1).

## Risk review

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| The filler is left on the TV, or fills it completely | low | high | One folder, a 256 MiB floor computed from a fresh `df`, and `try/finally` cleanup proven by EC-014's Ctrl+C dry run before first use. Every filler step ends with a `df` within 1 MiB of its start |
| The power cut corrupts something outside the app (system or other apps' data) | low | med | One cut only, last in order (engineering call 3), during an extract with no other writes running. Android's filesystems journal metadata. Jeff pulls the plug, so it's never automated |
| Resume appends to bytes from a changed object | low | high | `If-Range` with the stored validator, a `200` or changed `ETag` restarts from 0, and the final size and SHA-256 checks are unchanged. A bad resume can never install |
| `HttpURLConnection` drops `Range` on the redirect | med | med | The JVM harness checks it against the real GitHub URL before the TV run. If it drops, follow the redirect by hand (`setInstanceFollowRedirects(false)`, re-issue with `Range`), staying HTTPS-only as WP-085 requires |
| The sweep deletes a `.part` (the `onCreate` call found above) | high if missed | med | Scope item 15 reworded. EC-014 Step 4 relaunches the app between the kill and the retry, so the sweep runs before the resume |
| `getAllocatableBytes` overstates the space that can really be used on this TV | med | med | Exit criterion 11 measures it. A refusal is tested with a real filler, not only the override |
| `fsync` on every file slows the extract noticeably | med | low | Record extract time with and without for the synthetic package in §Result. Durability wins unless the cost is extreme; if it is, sync once per file at close rather than mid-stream |
| Private id leaks in a capture pasted into docs | low | high | Replace it with `<app-id>` in every quoted output (as EC-008 did); the grep exit check |
| Device evidence claimed without a capture (the 2026-11-21 lesson) | low | high | No EC-014 box is checked without a logcat excerpt, command output or screenshot. Jeff's power-cut confirmation is quoted as his |
| The TV has too little free space for the update test | med | med | The pre-execution stop rule (under 2 GiB free). Don't free space by deleting or uninstalling anything on the TV; ask Jeff |
